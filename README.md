# Showtakes

Ratings, reviews, and discussion of theatre productions: Letterboxd for the stage.

- Domain language: [CONTEXT.md](CONTEXT.md)
- Architecture decisions: [docs/adr/](docs/adr/)
- Ordered work list: [docs/TASKS.md](docs/TASKS.md)

## Requirements

- Node.js 24 or newer
- pnpm (version pinned in `package.json`)
- OrbStack (or another Docker runtime) for the local Postgres database

## Getting started

```sh
pnpm install
pnpm exec playwright install chromium   # once, for browser tests
cp .env.example .env                    # once, local settings
pnpm db:up                              # start Postgres (port 5433)
pnpm db:migrate                         # create or update the tables
pnpm dev                                # http://localhost:3000
```

## Commands

| Command            | What it does                                             |
| ------------------ | -------------------------------------------------------- |
| `pnpm dev`         | Run the site locally with live reload                    |
| `pnpm build`       | Production build                                         |
| `pnpm lint`        | Code checks, including the `src/core` import rules       |
| `pnpm typecheck`   | TypeScript type checking                                 |
| `pnpm test`        | Unit and integration tests (Vitest; needs `db:up`)       |
| `pnpm test:unit`   | Unit tests only, no database needed                      |
| `pnpm test:e2e`    | Browser tests (Playwright)                               |
| `pnpm db:up`       | Start the local Postgres container                       |
| `pnpm db:down`     | Stop it (data is kept in a Docker volume)                |
| `pnpm db:generate` | Write a SQL migration from changes to any `schema.ts`    |
| `pnpm db:migrate`  | Apply pending migrations to `DATABASE_URL`               |
| `pnpm db:studio`   | Browse the database in Drizzle Studio                    |

### Database tests

Files named `*.integration.test.ts` run against a throwaway database that
each `pnpm test` run creates, migrates, and drops (`src/db/testing/`). Test
files share it and run in parallel, so each test creates its own uniquely
named data, deletes it afterwards, and never assumes a table is empty.

To inspect what a failing test left behind, run `KEEP_TEST_DB=1 pnpm test`;
the database is kept and its name printed. Test databases older than a day,
including ones left by killed runs, are dropped at the start of each run.

## Layout

| Path              | Contents                                                      |
| ----------------- | ------------------------------------------------------------- |
| `src/app/`        | Pages and routes (Next.js App Router)                         |
| `src/components/` | Our own UI components, built on the shadcn/ui ones            |
| `src/shadcn/`     | Code generated by shadcn/ui (see below)                       |
| `src/core/`       | Business rules and operations, one folder per area (ADR 0004) |
| `src/db/`         | Database connection, migrations, and test-database helpers    |
| `e2e/`            | Browser tests                                                 |

`src/components/` is created by a later ticket.

### Business rules and operations

`src/core/` holds everything the site does, independent of the web pages
(ADR 0002, ADR 0004). It has one folder per section of [CONTEXT.md](CONTEXT.md)
(`people/`, later `catalog/` and `opinions/`), plus `shared/` for the Actor,
permission checks, and the Result type. Pages reach it only through
`createOperations({ db })` in `src/core/operations.ts`.

File names say what a file may do, and lint enforces it:

| File                         | Contents                                   |
| ---------------------------- | ------------------------------------------ |
| `<concept>.operations.ts`    | Operations; may use the database           |
| `schema.ts`                  | The area's tables                          |
| any other `.ts`              | Pure rules; no database imports allowed    |
| `*.test.ts`                  | Unit tests, no database                    |
| `*.integration.test.ts`      | Tests against the throwaway test database  |

An operation takes the Actor first. A permission refusal (something a correct
page never offers) throws `PermissionRefusedError`; an expected failure
(something a person can cause through a correct page) is returned as a
`Result`. `src/core/people/allowlist.operations.ts` is the reference example.

### Generated shadcn/ui code

`src/shadcn/` holds everything the shadcn/ui installer generates
(`pnpm dlx shadcn add <component>`); `components.json` points the installer
there. Keeping it separate marks which code we did not write, so it is exempt
from the project's commenting conventions and can be compared with newer
shadcn releases. It is still ours to edit: restyle these files freely. App code
should normally use our wrappers in `src/components/` rather than importing
from `src/shadcn/` directly.
